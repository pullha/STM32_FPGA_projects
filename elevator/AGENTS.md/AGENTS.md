# STM32 Project Rules

## Target

- MCU: STM32F411RET6
- Framework: STM32 HAL
- Build system: CMake generated by STM32CubeMX
- Operating system: Bare metal unless explicitly stated otherwise

## Generated code rules

- Do not modify the .ioc file unless explicitly requested.
- Do not change pin, clock, DMA or peripheral settings directly in generated C code.
- Hardware configuration changes must be made through STM32CubeMX.
- In CubeMX-generated files, edit only inside USER CODE BEGIN and USER CODE END sections.
- Do not modify files inside Drivers or Middlewares unless explicitly requested.
- Do not modify cmake/stm32cubemx/CMakeLists.txt because CubeMX regenerates it.

## Source file rules

- Place application source files in Core/Src.
- Place application header files in Core/Inc.
- Use HAL functions unless direct register access is explicitly requested.
- Keep interrupt service routines short.
- Do not use blocking delays inside interrupts.

## Build and hardware rules

- Run a Debug CMake build after source changes.
- Report all compiler errors and warnings.
- Do not flash or start a hardware debug session without approval.
- Never change MCU pin assignments without showing the proposed changes first.
